# 安居建业 PPT 助手内部版功能边界与保留说明

## 1. 员工可调用的产品能力

- 主题、提纲、文档、图片和对话生成；
- 固定安居建业标准模板的新演示；
- 旧 PPTX 原样导入后继续编辑；
- 页面编辑、AI 修改、动画、演示、演讲稿和历史恢复；
- 文字生成、AI 修改，以及所选模型支持时的扫描件识别；
- PPTX、PDF 和逐页 PNG 导出。

## 2. 已停用的调用入口

- 路由只保留首页、我的演示、设置、对话、生成中和演示编辑器。
- 自定义模板新增、导入、编辑、重命名和删除 IPC 不注册。
- 自定义风格、风格预览和用户字体管理 IPC 不注册。
- 启动时只同步公司 `anjian-corporate` 风格，并清理旧版本残留的系统通用风格。
- 编辑器不再提供通用风格页或模板保存入口。
- 长图、MP4、HTML/演示包、会话包和提纲文件导出 IPC 不注册。
- Token 用量不记录，统计 IPC 不注册；英文切换和公共更新不进入员工界面。
- 文本模型只允许 `openai` 或 `openai-responses` 兼容协议，员工通过受控 BYOK 预设选择阿里云百炼、腾讯 TokenHub、DeepSeek，或使用仅限 HTTPS 的高级自定义地址。
- 预设服务必须匹配官方域名；设置页在保存前披露实际数据目标域名。AI 生图在首版 BYOK 中默认关闭。

## 3. 打包时删除的资源

- `ffmpeg` 不进入内部安装包。
- 通用风格目录在 `afterPack` 阶段删除，只保留：
  - `resources/styles/anjian-corporate/`
  - `resources/styles/manifest.json`

## 4. 仍保留的共享底层

| 保留项 | 用途 | 员工能否配置 |
| --- | --- | --- |
| 字体读取、替换和嵌入代码 | 模板渲染、旧 PPTX 导入、PPTX/PDF 导出 | 不能 |
| 内置字体文件 | 缺字回退与导出兼容 | 不能 |
| 页面布局、图表、动画和来源读取 Skills | 公司模板生成与编辑 | 不能 |
| 非 16:9 布局兼容代码 | 读取员工旧 PPTX 和复用上游公共结构 | 不能新建此类画布 |
| 通用风格管理源文件 | 降低与上游合并成本；运行时不注册，打包时资源被删除 | 不能 |
| 旧导出实现源文件 | 降低一次性大删除风险；运行时通道不注册，ffmpeg 不打包 | 不能 |
| 英文翻译源文件 | 保持上游类型结构；应用只加载中文词典 | 不能切换 |
| 其他生图适配器源文件 | 保持上游代码结构；运行时提供者白名单会拒绝 | 不能 |

## 5. 安全边界

- 安装包不携带公司 AI 端点或员工 Key；服务地址、模型和 Key 由员工在本机设置。
- 阿里云百炼、腾讯 TokenHub、DeepSeek预设执行官方域名白名单校验；高级自定义只接受 HTTPS。
- AI 操作前检查配置；浏览、编辑、导出和旧 PPTX 本地导入不依赖 AI 配置。
- 员工 Key 使用 Electron `safeStorage` 加密后写入本机数据库。
- 无法使用安全存储时拒绝保存，不回退到明文。
- 主进程返回设置数据时只返回密钥占位符，不把文本或生图 Key 送入渲染进程。
- 旧版明文或无法解密的密钥视为未配置，要求员工重新输入。
- 日志只记录是否配置，不记录完整 Key。

## 6. 后续可继续物理删除的代码

试点稳定、且不再需要频繁合并上游版本后，可以单独安排一次代码瘦身：

1. 删除未注册的通用风格、字体管理和旧导出实现；
2. 删除对应渲染页面、Store 方法、IPC 类型和未使用依赖；
3. 重新做旧 PPTX、模板生成、编辑和三种导出的完整回归；
4. 比较安装包体积、启动时间和崩溃率后再合并。

当前采用“运行时不可调用 + 打包不带高风险资源 + 保留共享源码”的方案，是为了在不破坏核心编辑/导出链的前提下先完成可验收的内部版。
