## 0. 如何阅读和审核这份文档

本文使用三种状态：

- **已确认**：来自目前已明确提出的要求，可直接作为 v1 需求。
- **建议方案**：基于当前项目能力和内部软件风险给出的推荐，需审核确认。
- **待确认**：不同选择会明显影响工期、成本、使用体验或安全，不能由开发人员自行决定。

本文件是产品需求和验收依据，不代表程序已经完成。只有通过本文后续的 Windows 安装、功能、安全和模板验收，才能称为“可交付的 EXE”。

2026-07-23 两轮评审已确认：

- 导入员工以前制作的 PPTX 时保留原来的颜色和排版，只继续编辑，不自动改成公司模板。
- 软件内保留动画设置、预览和演示；原生动画导出不是 v1 发布的强制条件。
- 如果原生动画实现成本可控，则保留 PowerPoint / WPS 原生动画；否则导出所有内容可见的最终静态画面并明确提示。
- WPS Office 纳入正式兼容与验收范围。
- PDF 纳入参考资料读取范围。
- 单次生成限制为 1–50 页。
- v1 小范围内部试点接受未签名安装包。
- 软件界面品牌参考安居建业官网 `https://www.szajjy.com/`。
- 公司目前没有统一 AI 服务，v1 使用受控 BYOK：员工自行准备开发者 API Key。
- 预设支持阿里云百炼、腾讯 TokenHub、DeepSeek；高级用户可填写 HTTPS 的 OpenAI 兼容地址。
- 仅在员工执行 AI 操作时检查配置；浏览、编辑、导出和旧 PPTX 本地导入不要求 API Key。
- AI 生图在首版 BYOK 中默认关闭。

## 1. 一页摘要

### 1.1 要做什么

在开源项目 Oh My PPT / AJJY-ppt 的基础上，制作一款仅供安居建业内部员工使用的 Windows 桌面 PPT 制作工具，暂定名称为“安居建业 PPT 助手”。

员工可以输入主题、提纲或上传参考文档，让 AI 按安居建业公司模板生成演示文稿；也可以导入已有 PPTX，继续进行 AI 修改和可视化编辑，最后导出 PPTX、PDF 或逐页 PNG。

### 1.2 为什么要做

原项目是一款面向公众的通用 PPT 工具，包含大量模板、风格、画布比例、模型供应商和导出方式。直接给内部员工使用会带来四个问题：

1. **品牌不统一**：员工可能生成不符合公司规范的页面。
2. **操作复杂**：大量与内部工作无关的入口增加学习成本和误操作。
3. **安全边界不清**：员工可能填错 AI 地址，或在不知情时将内部资料发往错误服务。
4. **维护成本高**：保留越多通用功能，后续测试、升级和故障排查的范围越大。

### 1.3 v1 成功的定义

v1 达到以下结果才算成功：

- 员工能够在干净的 Windows x64 电脑上安装并启动软件，不需要安装 Node.js、Python 或开发工具。
- 软件名称、图标、Logo、界面色彩和默认文案符合安居建业内部风格。
- 所有“新建演示”固定使用安居建业 2024 年 6 月模板和 16:9 画布。
- 员工能完成“生成—编辑—保存—恢复历史—导出”的完整工作闭环。
- AI 只连接受控 BYOK 预设或员工明确填写的 HTTPS 兼容接口；界面披露数据目标，个人 Key 不明文保存、不进入日志、不写入安装包。
- 与内部使用无关的功能不仅从界面消失，相关路由、调用入口、打包资源和不再需要的依赖也完成清理或形成保留说明。
- 在真实 Windows 环境完成安装、重装升级、卸载、生成、编辑、导入和导出验收。

### 1.4 v1 不是什么

v1 不是完整替代 Microsoft PowerPoint 的排版软件，不做多人在线协作、云端账号体系、模板市场或公共 SaaS 服务。软件内可以设置和播放动画，但 v1 不把 PowerPoint / WPS 原生动画导出作为发布前置条件；员工导入的任意第三方 PPTX，也不承诺完整保留其中的宏、特殊对象和所有复杂动画。

## 2. 用户和职责

| 角色 | 主要工作 | 是否需要技术能力 |
| --- | --- | --- |
| 安居建业员工 | 新建、生成、编辑、演示和导出 PPT | 不需要 |
| 内部管理员 / IT | 发布可使用的服务建议、资料分级和网络规则；分发安装包 | 需要少量配置能力 |
| 品牌或综合管理人员 | 确认 Logo、颜色、字体、页脚和公司模板使用规则 | 不需要编程 |
| 开发维护人员 | 修改程序、构建安装包、修复问题和发布新版本 | 需要 |

### 2.1 不设置软件账号的影响

**已确认方向：v1 不设置登录账号。**

这样做的好处：

- 员工安装后即可使用，部署快、培训成本低。
- 不需要新建账号服务器、密码找回、权限后台和用户数据库。
- 演示文稿默认保存在本机，系统结构更简单。

不这样做或以后增加账号的好处：

- 可以做到人员权限、离职停用、操作审计和跨电脑同步。

当前选择的限制：

- 软件本身无法证明操作者一定是安居建业员工。
- 共享电脑上的其他用户可能打开本机已有项目。
- 内部身份控制主要依赖电脑账户、安装包分发范围和 AI 服务 Key。

因此，v1 适合“公司管理的办公电脑 + 内部分发”的场景，不应作为公开下载软件。

## 3. 给非技术评审人的 EXE 说明

### 3.1 EXE 到底是什么

本项目会产生两类 EXE：

1. **安装程序**：例如 `AnjuJianye-PPT-Assistant-1.0.0-x64-setup.exe`，员工双击它完成安装。
2. **应用程序**：安装后真正运行的“安居建业 PPT 助手”。

普通员工只需要安装程序，不需要源代码和开发环境。

### 3.2 为什么选择 Windows x64

**已确认方向：v1 先支持 Windows x64。**

“x64”指常见的 64 位 Intel/AMD Windows 电脑。这样做可以把第一版的测试范围控制在公司最常见的办公设备上。

好处：

- 安装包和测试范围较小，更容易保证稳定。
- 不需要同时解决 macOS 签名、公证和不同芯片兼容问题。

限制：

- Windows ARM、macOS、Linux 和手机不能使用。
- 如果公司仍有 32 位 Windows 电脑，v1 无法安装。

### 3.3 Electron 是什么，为什么沿用

当前项目使用 Electron：界面采用网页技术实现，但作为桌面软件运行。它会把运行所需环境一起装进 EXE。

沿用的好处：

- 不用推翻现有项目，可以继续利用已有生成、编辑、预览和导出能力。
- 普通员工无需另装浏览器插件、Node.js 或 Python。
- 同一套代码较容易维护。

代价：

- 安装包通常比传统小工具大。
- 内存占用通常高于纯原生 Windows 软件。

重写成原生 Windows 软件理论上可以更小，但会失去大量现成功能，成本和风险远高于本次内部改造，因此不建议。

### 3.4 “可离线安装”不等于“可离线生成”

安装包应包含软件运行所需组件，因此安装时不应再下载开发依赖。但是 AI 生成、AI 修改和 AI 生图必须连接管理员指定的 AI 服务。

- 无网络时：可以打开本地项目并进行部分手工编辑、预览和导出。
- 无法连接 AI 服务时：不能进行 AI 生成、AI 修改、演讲稿生成和 AI 生图。

软件必须明确提示“网络不可用”“Key 无效”或“服务未配置”，不能只显示模糊的“生成失败”。

### 3.5 EXE 签名为什么重要

Windows 代码签名相当于给安装包加上可验证的公司发布者身份。

有签名的好处：

- Windows 更容易显示可信发布者。
- 降低 SmartScreen 或杀毒软件拦截概率。
- 员工更容易确认安装包没有被第三方替换。

不签名的好处：

- 小范围试点可以更快开始，不需要先采购或申请证书。

不签名的风险：

- Windows 可能显示“未知发布者”或“Windows 已保护你的电脑”。
- 员工可能无法判断安装包是否可信，部分公司安全策略会直接阻止安装。
- 每次新版本都可能重新积累信誉。

**已确认：v1 小范围受控试点接受未签名安装包。**

试点分发时必须同时提供安装包哈希值、来源说明和 Windows 警告处理指引。正式向全公司扩大分发前，仍建议由公司 IT 决定并配置代码签名。

## 4. 产品目标和非目标

### 4.1 产品目标

1. **统一品牌**：软件界面和新建 PPT 使用同一套安居建业视觉语言。
2. **统一模板**：员工无需选择模板，所有新建演示默认使用公司模板。
3. **降低门槛**：员工通过主题、提纲、文档或对话即可开始制作。
4. **保留可编辑性**：导出的 PPTX 能在 PowerPoint 中继续编辑常规文字、图片和基础图形。
5. **缩小功能面**：移除对内部没有价值的入口和后台能力。
6. **保护内部资料**：预设服务校验官方域名，自定义地址仅限 HTTPS，明确披露数据去向，Key 安全保存，默认不做公共遥测或自动上传。
7. **便于维护**：安装、升级、数据保留和问题排查都有明确方式。

### 4.2 v1 非目标

- 不做在线模板商城或社区模板下载。
- 不允许员工导入、创建、保存或切换自定义模板。
- 不做多人同时编辑、在线评论或云端同步。
- 不做公开注册、登录、会员、付费或订阅功能。
- 不支持竖版、方形、社交媒体画布和 4:3 画布。
- 不支持 MP4、HTML、长图、会话包等非必要导出。
- 不接入公共自动更新服务。
- 不把软件注册为系统默认的 `.pptx` 打开程序。
- 不承诺 100% 复刻任意第三方 PPTX 的所有动画、宏、嵌入对象和特殊字体。

## 5. 产品范围与优先级

### 5.1 P0：v1 必须完成

#### FR-01 公司品牌化

**需求**

- 产品名称统一为“安居建业 PPT 助手”。
- 应用图标、安装程序图标、窗口标题、快捷方式和卸载列表名称保持一致。
- 界面以暖白为底色，使用公司模板中的红、橙、黄和中性灰作为主要视觉语言。
- 中文界面为唯一用户界面，不显示语言切换。
- Logo 必须来自公司确认的正式资源。

**为什么做**

员工看到的安装包、应用和生成结果必须属于同一品牌体系，避免“换了模板但还是第三方软件”的割裂感。

**不做的后果**

容易造成工具来源不清、员工不信任，以及对外展示时出现第三方产品名称或错误 Logo。

**验收**

- 安装、启动、首页、编辑器、设置、历史页面和导出提示中不出现 Oh My PPT 的产品名或旧品牌图标。
- 品牌负责人对关键页面截图和应用图标签字确认。

#### FR-02 固定公司模板

**需求**

- 内置模板以附件 `安居建业PPT模板（2024年6月）.pptx` 为当前事实依据。
- 模板为 16:9，当前包含封面、目录、章节页、内容页和结束页五类基础页面。
- 所有新建演示固定使用该模板，不出现模板选择页。
- 保留模板中的 Logo、红橙黄波浪、页码和“内部文件 请勿外传”页脚。
- AI 只能在既有版式语言内组织内容，不得自行替换为霓虹、玻璃拟态、外部品牌色或无关装饰。
- 模板按版本管理。以后模板升级时，新项目使用新版本，已有项目不被静默覆盖。

**为什么做**

固定模板可以保证员工不懂设计也能生成基本统一的公司材料。

**做的代价**

视觉自由度降低；特殊活动或子品牌材料可能需要开发人员新增经公司批准的模板版本。

**不做的后果**

员工仍需判断模板和风格，无法真正解决内部 PPT 不统一的问题。

**验收**

- 新建 5 页、10 页和 20 页演示时均保持 16:9 和公司页脚。
- 封面、目录、章节、正文、结束页与原附件逐页对照。
- 不提供“自定义模板”“模板市场”“保存为模板”“删除公司模板”等入口或后台调用能力。

#### FR-03 从主题或提纲生成

**需求**

- 员工输入主题、受众、汇报目的、希望页数和详细提纲后可开始生成。
- 页数必须可编辑，生成前显示最终主题、页数和提纲供员工确认。
- 生成过程中显示总体阶段、当前页、成功页、失败页和可理解的错误。
- 支持取消和失败页重试，不因单页失败损坏已完成页面。

**为什么做**

这是员工从零开始制作 PPT 的最短路径。

**验收**

- 在有效 AI 配置下能从一段中文需求生成完整演示。
- 取消后任务停止且已有数据状态一致。
- 个别页面失败时可以重试，不需要整套重做。

#### FR-04 从参考文档生成

**需求**

- v1 支持读取 `.docx`、`.md`、`.txt`、`.csv`、`.pdf` 作为参考资料。
- 可读取 `.png`、`.jpg`、`.webp` 图片或截图并整理成可读参考说明。
- 普通文本型 PDF 应直接提取文字、标题和基础表格；扫描型 PDF 应按页转为图像并通过 OCR 或员工选择的具备视觉能力的模型识别。
- 上传后先给出 AI 建议的主题、页数和提纲，员工确认后再生成。
- 文档中的关键数据、专有名词和结构不得无依据改写。
- 软件应提示员工：参考资料会发送到设置页显示的目标域名进行分析。

**为什么做**

内部汇报往往已有 Word、表格摘录或文字材料，逐段复制会浪费时间。

**限制**

- PDF 中的复杂表格、多栏排版、手写内容或低清晰度扫描件可能无法完全还原；识别质量不足时必须提示员工核对，不能把不确定内容当成准确事实。
- Word 中的复杂图表、批注、页眉页脚和内嵌对象可能无法完整读取。
- CSV 适合作为结构化文字参考，不等于完整 Excel 分析能力。

**验收**

- 五种文档格式和三种图片格式各使用至少一个样例测试。
- PDF 必须分别用普通文本 PDF 和扫描型 PDF 验收；识别失败时应指出具体页码并允许员工取消或继续。
- 生成大纲能追溯到原资料结构，不能把普通多章节文档错误压缩成一页。

#### FR-05 对话梳理后生成

**需求**

- 员工可通过多轮对话补充受众、核心观点、结构、数据和表达要求。
- 生成前形成可见、可修改的最终提纲。
- 对话结果生成时仍固定使用公司模板。

**为什么做**

有些员工只有模糊想法，需要先和 AI 梳理，而不是立即出页。

**做的代价**

会增加界面和任务状态复杂度，也会产生额外 AI 调用。

**验收**

- 对话内容能够转成结构化提纲。
- 员工未确认最终提纲前不自动生成整套 PPT。

#### FR-06 导入现有 PPTX 继续编辑

**这里的“现有 PPTX”是什么意思**

它指员工电脑里以前已经用 PowerPoint 或 WPS 做好的 `.pptx` 文件。例如：

> 员工已有一份“2025 年项目总结.pptx”，现在想把它导入安居建业 PPT 助手，让 AI 帮忙修改文字、补页面或调整排版。

它不是指本项目附带的公司模板，也不是指软件刚生成的 PPT。

导入后有两种产品处理方式：

- **方案 A：保留原 PPT 的外观后继续编辑。** 原文件是什么颜色和版式，导入后尽量保持原样；员工可以再手工或通过 AI 修改。
- **方案 B：导入后自动改成安居建业模板。** 内容被重新排版到公司封面、目录、章节和正文页中。

**已确认采用方案 A。**

- 员工可导入已有 `.pptx`，转换为软件中的可编辑页面。
- 导入只用于当前项目的二次编辑，不把该 PPTX 保存成新模板。
- v1 默认尽量保留原 PPTX 的外观，不自动强制套用公司模板。
- “一键转换为安居建业模板”不属于 v1；如果以后需要，应作为单独功能评估，不与普通导入混在一起。

**为什么这样建议**

自动把任意 PPTX 强行套入公司模板，可能造成文字溢出、图表错位和信息丢失；“先可靠导入并继续编辑”更适合第一版。

**不采用该建议的另一种方案**

导入后立即转成公司模板。好处是风格更统一，缺点是转换质量和人工校对成本明显上升。

**验收**

- 普通文字、图片、基础形状和页面顺序能够导入。
- 对不支持的动画、宏、嵌入对象或字体给出明确警告。
- 导入项目不会出现在模板列表中。

#### FR-07 AI 修改

**需求**

- 支持对当前元素、当前页、选中多页或整套演示提出修改要求。
- 修改前明确作用范围，避免一句话误改整套演示。
- AI 修改后自动检查页面是否可渲染、是否超出画布、是否破坏公司固定元素。
- 每次修改形成可撤销的版本记录。

**为什么做**

“先生成再修改”才是实际工作流程，只有一次性生成不能形成可用工具。

**验收**

- 文字改写、布局调整、增删页面、图片替换等常见操作有可重复测试。
- 公司 Logo、页脚和基础装饰不能被普通 AI 指令意外删除。

#### FR-08 可视化编辑

**需求**

- 支持选择和编辑常见文字、图片、形状、图表等元素。
- 支持页面新增、删除、复制、重排和标题修改。
- 保存时不要求员工理解 HTML 或项目目录。
- 软件崩溃或关闭后，已保存内容可恢复。

**为什么做**

AI 结果通常需要人工微调；如果每次小改动都要再次调用 AI，会慢且增加成本。

**限制**

它不是完整 PowerPoint，复杂 SmartArt、宏、三维对象和所有母版能力不在 v1 范围。

#### FR-09 动画和演示

**已确认：保留软件内动画，原生动画导出不作为 v1 强制要求**

- 保留软件内的动画设置、预览和全屏演示。
- 支持常见的逐项出现或点击揭示。
- 如果技术验证表明成本和兼容性可控，可把“出现、淡入、擦除、单击逐项出现”等效果导出为 PowerPoint / WPS 原生动画。
- 如果不能可靠导出原生动画，PPTX 必须使用动画播放完成后的最终静态状态，保证所有文字、图片、图表和其他信息可见。
- 导出前或导出完成后明确提示“软件内动画已转为静态画面”，不能让员工误以为动画仍会在 PowerPoint / WPS 中播放。
- 不允许出现因动画初始隐藏状态被直接导出，导致正文或关键结论在 PPTX 中消失的情况。

**为什么这一项开发风险较高**

当前项目的页面以 HTML 方式渲染，网页动画与 PowerPoint 动画是两套不同格式。要满足原生动画要求，需要在导出时把页面元素、动画类型、顺序、触发方式和时间转换成 PPTX 内部动画结构，并同时验证 PowerPoint 和 WPS。

因此，实施时可以先做一次有时间边界的“原生动画导出技术验证”。如果现有导出库不能低风险实现，则使用上述静态最终画面方案，不为此更换整套导出技术或阻塞 v1 发布。

**边界**

软件内动画仍是 v1 功能。原生动画导出属于增强项；导入任意第三方 PPTX 时，其中的宏、路径动画、三维动画或插件动画不保证完整保留。

#### FR-10 演讲稿

**需求**

- 可按整套演示或当前页生成中文演讲稿。
- 演讲稿在软件中可查看、编辑和重新生成。
- 页面内容改变后提示演讲稿可能已经过期。

**当前建议**

- v1 将演讲稿作为本地 Markdown 文稿保存和查看。
- 是否必须写入 PPTX 的 PowerPoint“备注”区，列为待确认。

#### FR-11 AI 生图

**已确认方向**

- AI 生图在首版 BYOK 中默认关闭，不作为 v1 试点的阻断能力。
- 后续只有在公司明确数据边界、服务商、费用和版权规则后才重新开放。
- 重新开放时，生图失败不得影响当前 PPT 的其他内容。

**为什么做**

可以减少临时寻找配图的时间。

**不做或暂时关闭的好处**

降低模型费用、版权和内容合规风险，也避免员工误以为文字模型的 Key 必然具备生图权限。

#### FR-12 历史版本和撤销

**需求**

- AI 修改和主要手工修改形成历史记录。
- 员工可以查看变更、撤销和恢复。
- 恢复历史前提示会影响哪些页面。

**为什么做**

AI 修改具有不确定性，没有历史恢复会让员工不敢使用批量修改。

**验收**

- 至少覆盖单页修改、整套修改、删除页面和恢复操作。
- 恢复后数据库记录与实际页面文件一致。

#### FR-13 导出

**已确认只保留**

1. 可编辑 PPTX。
2. PDF。
3. 逐页 PNG。

**导出要求**

- 导出前检查缺页、失败页、资源丢失和页面渲染错误。
- 导出过程显示进度，员工可选择保存位置。
- 导出完成后显示实际路径。
- PPTX 优先保留文字、图片和基础图形的可编辑性；遇到无法编辑的复杂内容时显示警告。
- PDF 和 PNG 以最终视觉一致性为主，不承诺可编辑。

**为什么砍掉其他格式**

MP4、HTML、长图、会话包等会增加 ffmpeg、播放器、压缩、平台兼容和安全测试范围，但不属于当前内部核心流程。

**不保留这些格式的代价**

有视频或网页分享需求时，需要使用其他工具或后续单独立项。

#### FR-14 历史项目

**需求**

- 首页或历史页显示本机已有演示，支持打开、重命名和删除。
- 删除必须二次确认，并明确是移到回收站还是永久删除。
- 默认按最近更新时间排序，可按名称搜索。
- 项目内容和资源保存在用户选择或管理员规定的本地目录。

**建议方案**

删除优先采用可恢复方式；如果当前技术方案只能永久删除，界面必须明确写明。

#### FR-15 AI 设置

**已确认方向**

- 公司目前没有统一 AI 服务，v1 使用受控 BYOK，安装包不携带公司端点或个人 Key。
- 员工可选择阿里云百炼、腾讯 TokenHub、DeepSeek，填写对应的开发者 API Key 和模型 ID。
- 高级自定义仅支持 OpenAI 兼容协议和 HTTPS 地址，并明确提示其数据将发送到该域名。
- 预设服务校验官方域名，不能把仿冒地址伪装成官方预设。
- 设置页提供“测试并保存”，成功后才启用 AI 操作。
- 软件启动时不强制配置；只有生成、AI 修改、扫描件识别等 AI 操作才提示。
- 浏览、编辑、导出和旧 PPTX 本地导入不要求 API Key。

**为什么做**

公司无需先建设统一 AI 网关，员工可以用已有服务快速试点；域名校验、HTTPS 限制和目标披露降低填错接口的风险。

**做的代价**

员工需要自行开通开发者 API、承担或遵守额度规则；公司难以统一审计费用和停用凭据。BYOK 不等于资料可任意外发，仍需公司制定允许使用的资料等级和服务范围。

#### FR-16 错误、进度和诊断

**需求**

- 错误信息使用中文并说明用户下一步能做什么。
- 区分：未配置、Key 无效、网络不可达、模型不存在、超时、内容过长、生成失败、磁盘不可写、导出失败。
- 本地保留脱敏诊断日志，不自动上传。
- 日志不得包含完整 API Key；对内部正文、文件路径和模型响应应尽量减少记录。
- 建议提供“打开日志目录”或“导出脱敏诊断包”供员工手工提交给 IT。

**为什么做**

内部 EXE 发布后，开发人员通常不能直接看到员工电脑。没有可理解的错误和日志，任何问题都会变成“软件不能用”。

#### FR-17 真正移除非内部功能

**需求**

以下功能应从用户界面、页面路由、调用入口、打包资源和无必要依赖中清理：

- 通用模板市场、模板新建、模板导入、模板重命名和模板删除。
- 通用风格库、风格导入、风格切换和收藏。
- 用户自定义字体管理页面；但为正常渲染和导出所需的字体处理能力可以保留。
- Token 统计和成本看板。
- 英文界面和语言切换。
- 4:3、9:16、3:4、1:1 等非公司画布。
- MP4、HTML、长图、会话包等非批准导出。
- 公共自动更新、赞助、社区、开源宣传和非内部入口。
- 未批准的模型供应商和任意服务地址配置。

**验收原则**

仅把菜单隐藏不算完成。如果某项能力因共享底层逻辑必须保留，开发人员需要列出保留文件、用途和无法删除的原因，并保证员工无法调用。

### 5.2 P1：建议在试点后补充

- 签名后的正式安装包。
- 内部更新渠道或 IT 静默分发方案。
- 一键导出脱敏诊断包。
- PowerPoint / WPS 原生动画导出；只有技术验证表明成本和兼容性可控时才提前进入 v1。
- 将演讲稿写入 PPTX 备注。
- 经品牌部门批准的第二套特殊场景模板。
- 更细的内部资料分级和上传提醒。

### 5.3 明确不做

- 公网注册登录、计费和会员。
- 云端项目库、多人在线协同。
- 模板市场和用户自定义模板。
- 与 PPT 制作无关的公共模型市场、自动推荐和随意回退。
- macOS、Linux、手机和平板版本。
- 公共自动更新服务器。

## 6. 关键业务流程

### 6.1 首次安装和配置

```text
IT 准备安装包、BYOK 使用说明和资料分级规则

  → 点击“测试并保存”
  → 成功后返回原 AI 操作
```

要求：

- 安装不要求员工安装开发软件。
- 预设服务校验官方域名；高级自定义只接受 HTTPS，并显示实际目标域名。
- 测试失败时给出具体原因，不保存无效 Key。
- 首次使用前提示：哪些资料会留在本机，哪些内容会发送到 AI 服务。

```text
输入主题/目的/受众/页数/提纲
  → 系统检查 AI 配置
  → 显示最终生成计划
  → 员工确认

  → AI 按页生成并实时显示进度

  → 进入编辑器
```

```text
上传参考资料
  → 本地读取并准备可分析内容

  → 员工修改并确认
  → 按公司模板生成

```

```text
选择 PPTX
  → 检查文件和保存目录

  → AI 或手工修改
```

### 6.5 编辑和历史恢复

```text
选择元素/页面/多页/整套
```

```text

  → 选择保存位置

  → 输出文件

```

## 7. 品牌与模板规范

### 7.1 当前品牌事实来源

**已确认的公司官网：`https://www.szajjy.com/`。**

品牌使用边界如下：

1. 软件 Logo、应用界面色彩、导航和品牌气质以安居建业官网为主要参考。
2. PPT 的页面类型、固定装饰、页脚和 16:9 结构以用户提供的 `安居建业PPT模板（2024年6月）.pptx` 为主要依据。
3. 官网当前使用 `/images/logo.png` 作为页面 Logo 资源；实施时应直接核对该正式资源，不能根据截图手工重画。
4. 官网样式可核对到红色、橙色、暖金色、白色和灰色体系，其中橙色 `#F5831F` 与附件模板一致。最终应用色板应同时通过官网截图和附件模板对照。
5. 如果公司以后提供品牌手册或矢量 Logo，应以更新、更高质量的正式文件替换网页位图，但不改变已经确认的品牌方向。

### 7.2 模板视觉规则

- 画布：16:9，内部渲染基准 1600 × 900。
- 背景：白色或暖白色。
- 主色：以模板中的红、橙、黄为主，灰色用于正文和辅助信息。
- 字体：优先使用 Microsoft YaHei；缺失时使用经确认、可合法分发或系统自带的中文无衬线字体。
- 页面类型：封面、目录、章节、内容、结束。
- 固定元素：公司 Logo、页码、波浪装饰和“内部文件 请勿外传”。
- 图表：扁平二维，不使用无关品牌色、三维效果和霓虹色。
- 版式：保持留白和清晰层级，正文不得覆盖固定元素。

### 7.3 模板更新

公司以后替换模板时，应由开发人员制作新的版本号并随软件升级发布：

- 新建项目默认用最新批准版本。
- 已有项目继续保留创建时的模板资源。
- 不在后台静默修改员工已完成的 PPT。
- 模板更新需要重新做五类页面和导出验收。

这样做会占用更多磁盘，但可以避免旧项目突然变样。

## 8. 数据、安全和隐私要求

### 8.1 数据分别存在哪里

本机保存：

- 项目名称、创建时间、状态和历史记录。
- 每页实际内容、图片、附件、导出文件和演讲稿。
- 个人 API Key 的加密结果。
- 脱敏后的本地运行日志。

发送到员工选择且设置页已明确披露域名的 AI 服务：

- 员工输入的生成或修改指令。
- 为完成任务所需的页面内容。
- 员工主动上传并用于分析的文档或图片内容。

默认不应发送：

- 与当前任务无关的其他本机文件。
- 完整 API Key。
- 全盘目录或浏览历史。
- 自动遥测、广告或公共统计。

### 8.2 API Key 保存

**强制要求**

- 使用 Windows 系统级加密能力保存 Key。
- 如果系统加密不可用，软件不得退回明文保存。
- 可选择要求员工每次输入，或直接阻止保存并给出提示。
- Key 不进入日志、不进入截图、不进入项目导出、不进入安装包。

为什么不能明文保存：

明文 Key 一旦被日志、备份或其他本机用户读取，可能导致服务被冒用和费用损失。

### 8.3 内部资料提示

首次使用和首次上传资料前应有简洁提示：

> 生成和修改所需内容将发送到设置页显示的 AI 服务域名。请在发送前确认目标，并遵守公司资料分级和保密要求，不上传未经允许处理的资料。

是否允许“机密”“敏感个人信息”等具体资料进入该 AI 服务，需要公司 IT、信息安全或法务确认，不能仅由软件开发判断。

### 8.4 本地数据与卸载

**建议方案**

- 软件卸载默认只移除应用，不自动删除员工项目。
- 如需清空本地数据，提供单独、醒目且二次确认的操作。
- 升级安装必须保留项目、历史和设置。

好处是避免员工误删成果；代价是卸载后电脑上仍保留项目文件，需要 IT 在设备回收时按制度清理。

## 9. Windows 安装和升级要求

### 9.1 安装方式

**建议方案**

- 使用标准 NSIS 安装程序。
- v1 默认按当前 Windows 用户安装，尽量不要求管理员权限。
- 允许员工选择安装目录。
- 创建桌面和开始菜单快捷方式。
- 安装结束后不自动启动，避免在管理员或代装场景下启动到错误账户。

按用户安装的好处是部署简单；缺点是同一台电脑的其他 Windows 用户需要分别安装。如果公司要求所有用户共用一次安装，则需改为按机器安装，并由 IT 提供管理员权限。

### 9.2 安装包内容

安装包应包含：

- 应用运行环境。
- 安居建业品牌资源。
- 公司固定 PPT 模板。
- 公司样式规则。
- 非敏感的 AI 服务和模型配置。

安装包不得包含：

- 员工 API Key。
- 开发人员的本机路径、测试数据和数据库。
- Git 仓库、测试代码、源码映射和无关模板资源。
- 未批准的公共服务地址。

### 9.3 升级

**已确认方向：v1 不连接公共自动更新。**

建议由 IT 分发新版安装程序，员工直接覆盖安装。升级必须：

- 保留项目和个人设置。
- 识别旧模板项目，不强制改版。
- 版本号可在“关于”或设置页查看。
- 新旧版本不允许同时写同一项目造成损坏。

不做自动更新的好处是内部可控、不会连接外部更新服务；缺点是 IT 需要通知和推动升级。

### 9.4 卸载

- 在 Windows“已安装的应用”中可正常卸载。
- 卸载项显示正确产品名和图标。
- 默认保留项目数据。
- 卸载后不能残留自动启动项或无效快捷方式。

## 10. 非功能要求

### 10.1 兼容性

- Windows 11 x64。
- PowerPoint 2019、2021 或 Microsoft 365 桌面版。
- WPS Office Windows 桌面版；正式验收使用公司实际安装的 WPS 版本。

公司仍需提供实际使用的 WPS 完整版本号。版本不同可能影响字体、图形、备注和动画兼容性；如果暂时无法提供，试点时应记录测试电脑上的 WPS 版本，不能笼统写“已支持所有 WPS”。

### 10.2 稳定性

- 单页失败不应导致整套项目无法打开。
- 保存采用安全写入，避免中途断电留下半个文件。
- 生成、导入和导出支持明确的进行中状态，防止重复点击。
- 应用异常退出后重新打开，最近一次成功保存的版本仍可使用。
- 不覆盖员工导入的原始 PPTX 和参考文档。

### 10.3 性能

- 普通办公电脑上，启动后应在合理时间内进入首页。
- 页面切换和常见手工编辑应即时响应。
- AI 生成时间受模型、网络和页数影响，不承诺固定秒数，但必须持续显示进度，避免看起来“卡死”。
- **已确认：v1 单次生成页数限制为 1–50 页。**
- 超过 50 页时不直接生成，提示员工拆分为多份演示，以控制费用、等待时间和失败概率。

### 10.4 可用性

- 员工主流程最多围绕“新建、历史、设置”三个一级入口。
- 关键按钮使用中文动词，例如“开始生成”“测试连接”“导出 PPTX”。
- 危险操作必须二次确认。
- 不用 Token、IPC、Provider、Endpoint 等技术词直接面向普通员工；必要时使用“服务地址”“模型”“个人密钥”等说明。

### 10.5 网络

- 支持公司常见代理和 HTTPS。
- 如果 AI 服务使用内部证书，需在目标 Windows 电脑验证证书链。
- 网络超时后允许重试，不应无限等待。
- 软件不能在未告知的情况下切换到公共备用 AI。

## 11. 功能裁剪的利弊总表

| 决策 | 做的好处 | 做的代价 / 不做的好处 |
| --- | --- | --- |
| 固定公司模板 | 统一、简单、少误操作 | 特殊场景灵活性降低 |
| 只保留中文 | 培训和维护更简单 | 外籍或英文界面用户无法使用；PPT 内容本身仍可为英文 |
| 只支持 16:9 | 与公司模板一致、导出测试少 | 不能制作竖版海报和老式 4:3 |
| 受控 BYOK 预设 + HTTPS 自定义 | 无需先建设统一网关，服务切换灵活，数据目标可见 | 公司较难统一费用和凭据审计；需要资料分级制度 |
| 员工使用个人 Key | 可单独停用、费用可追踪到凭据 | 员工首次需要开通开发者 API；网页会员不能替代 |
| 不做登录 | 安装即用、无账号系统 | 软件自身没有人员权限和集中审计 |
| 不做模板市场 | 避免外部模板和品牌混乱 | 无法快速尝试其他视觉风格 |
| 不做 Token 看板 | 界面简单 | 员工看不到详细用量；费用应由服务端管理 |
| 只导出 PPTX/PDF/PNG | 覆盖内部核心工作，减少依赖 | 视频和网页分享需其他工具 |
| 不做公共自动更新 | 发布可控、减少外部连接 | IT 需要手工分发升级 |
| 小范围试点不签名 | 快速试用、无证书前置 | Windows 可能警告或拦截 |
| 卸载保留项目 | 降低误删风险 | 设备回收时需另行清理数据 |
